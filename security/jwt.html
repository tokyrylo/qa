Bearer Token и JWT — твой цифровой пропуск

Когда ты получил токен (браслет), сервер и клиент используют его, чтобы подтверждать твою личность при каждом запросе без постоянного ввода пароля. Что такое Bearer Token?

Bearer Token — это тип токена, который просто говорит серверу:

    «Я — тот, за кого себя выдаю, просто посмотри на этот токен».

Ты кладёшь этот токен в HTTP-заголовок:

Authorization: Bearer <твой_токен>

Слово Bearer буквально значит «носитель» — тот, кто держит этот токен, имеет доступ.

А что такое JWT?

JWT (JSON Web Token) — самый распространённый формат для таких токенов. Это компактная строка, которая содержит:

  • Header (заголовок) — указывает, как токен подписан.

  • Payload (полезная нагрузка) — информация о пользователе и сроке действия токена (например, кто ты, когда токен истекает).

  • Signature (подпись) — защищает токен от подделки.

JWT выглядит как три части, разделённые точками:

xxxxx.yyyyy.zzzzz

Почему JWT удобен?

  • Серверу не нужно хранить информацию о токенах — всё в самом JWT.

  • Можно быстро проверить, что токен настоящий и не изменён (благодаря подписи).

  • В payload можно хранить полезные данные, например роль пользователя.

Как это работает в жизни?

  • Ты входишь в систему — отправляешь логин и пароль.

  • Сервер отдаёт тебе JWT — твой цифровой браслет.

  • При каждом запросе ты отправляешь JWT в заголовке Authorization.

  • Сервер проверяет подпись токена и срок действия. Если всё хорошо — разрешает доступ.

Пример заголовка с Bearer Token:

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

💡 Аналогия с рестораном:

Bearer Token — это как браслет с QR-кодом, который охранник сканирует, чтобы удостовериться, что ты можешь заходить и заказывать.

Пример использования JWT в запросах и проверка на сервере

Клиент: Отправка запроса с JWT

После того, как клиент получил токен, он кладёт его в заголовок Authorization:

GET /api/user/profile HTTP/1.1
Host: api.example.com
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Accept: application/json

Это значит:

    «Я — этот пользователь, и вот мой цифровой пропуск (JWT), проверь, пожалуйста.»

Сервер: Проверка JWT

Когда сервер получает такой запрос, он:

  • Извлекает токен из заголовка Authorization.

  • Проверяет подпись токена, чтобы убедиться, что он не подделан.

  • Проверяет срок действия (токен может быть просрочен).

  • Извлекает данные пользователя из токена (например, ID или роль).

  • Если всё верно — разрешает выполнить запрос и отдаёт нужные данные.

  • Если нет — отвечает ошибкой, например 401 Unauthorized.
