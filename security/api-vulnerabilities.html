🔒 Проверка уязвимостей API

API — это не только данные и функциональность, но и потенциальные точки атаки. QA должен уметь проверять основные уязвимости, чтобы предотвратить проблемы с безопасностью.

📌 Основные виды уязвимостей

  1. Недостаточная авторизация
  2. Пользователь получает доступ к ресурсам, к которым не должен иметь доступа.

  3. Примеры проверки:

    • Попробовать получить данные другого пользователя через GET /users/{id}
    • Изменить данные чужого ресурса через PUT/PATCH/DELETE

  4. Утечка токенов или ключей

  5. Токены доступа (JWT, Bearer) видны или хранятся небезопасно.

  6. Примеры проверки:

    • Проверить токен в URL или логах
    • Попробовать использовать чужой токен

  7. SQL / NoSQL инъекции

  8. Ввод специальных символов для обхода фильтров и получения несанкционированных данных.

  9. Примеры:

    • Вставка ' OR 1=1 -- в параметры запроса
    • Проверка обработки специальных символов в фильтрах

  10. XSS (Cross-Site Scripting)

  11. Если API возвращает данные, которые затем отображаются в веб-приложении.

  12. Пример:

    • Вставка <script>alert(1)</script> в текстовые поля
    • Проверка, экранируются ли символы при возврате ответа

  13. CSRF (Cross-Site Request Forgery)

  14. Нежелательные действия выполняются от имени пользователя без его ведома.

  15. Пример:

    • Проверить защищённые POST/PUT/DELETE эндпоинты без токена или с поддельным токеном

  16. Неправильная обработка ошибок

  17. Сервер возвращает подробные ошибки, раскрывая внутренние данные.

  18. Пример:

    • Отправка некорректного запроса и проверка, не выводится ли стек-трейс или информация о базе данных

  19. Rate limiting / DoS

  20. Проверка ограничений на количество запросов для предотвращения перегрузки.
  21. Пример:
    • Быстрое многократное выполнение одного запроса
    • Проверка ответа сервера (429 Too Many Requests)

🛠 Инструменты для проверки

  • Postman / Insomnia — ручное тестирование эндпоинтов
  • OWASP ZAP — автоматизированное сканирование уязвимостей
  • Burp Suite — продвинутое тестирование безопасности
  • Curl / HTTPie — ручные тесты с командной строки
  • Automated QA Scripts — Python/JS скрипты для проверки токенов, прав доступа и валидации

✅ Рекомендации QA

  • Всегда проверять авторизацию и права доступа на каждом эндпоинте.
  • Пробовать как позитивные, так и негативные сценарии.
  • Проверять обработку ошибок и корректность кодов ответа.
  • Использовать как ручное тестирование, так и автоматические сканеры.
  • Документировать найденные уязвимости и повторно проверять после исправлений.
