# Типы API

`API` бывают разных видов — в зависимости от того, как они устроены и как обмениваются данными. Рассмотрим основные типы:

1. **REST API (Representational State Transfer)**:

    - Самый популярный и простой тип API, который использует стандартные HTTP-запросы.

    - Работает по принципу ресурсов: каждый ресурс (например, пользователь, товар) имеет свой URL.

    - Использует стандартные HTTP-методы:

        - `GET` — получить данные

        - `POST` — создать новый ресурс

        - `PUT` — обновить ресурс

        - `DELETE` — удалить ресурс

    - Формат данных обычно JSON — удобный для чтения и обработки.

**Аналогия с рестораном**:
`REST` — это официант, который знает, как приносить блюда по заказу, заменять их или убирать, используя понятные команды.

**Пример запроса GET (получить информацию о пользователе):**

```json
GET /users/123 HTTP/1.1
Host: api.example.com
Accept: application/json
```
**Пример ответа:**

```json
{
  "id": 123,
  "name": "Иван",
  "email": "ivan@example.com"
}
```
**Пример запроса POST (создать нового пользователя):**
```json
POST /users HTTP/1.1
Host: api.example.com
Content-Type: application/json

{
  "name": "Ольга",
  "email": "olga@example.com"
}
```

**Пример ответа:**

```json
{
  "id": 124,
  "name": "Ольга",
  "email": "olga@example.com"
}
```

2. **SOAP (Simple Object Access Protocol)**:

    - Более старый и строгий стандарт обмена сообщениями между программами.

    - Использует XML для передачи данных — сложнее читать и писать.

    - Очень формален: описывает, какие операции доступны и как их вызывать.

    - Часто применяется в корпоративных и банковских системах.

**Пример SOAP-запроса (получить информацию о пользователе):**

```xml
<soap:Envelope xmlns:soap="http://www.w3.org/2003/05/soap-envelope">
  <soap:Body>
    <GetUserDetails xmlns="http://example.com/">
      <UserId>123</UserId>
    </GetUserDetails>
  </soap:Body>
</soap:Envelope>    
```
**Пример SOAP-ответа:**

```xml
<soap:Envelope xmlns:soap="http://www.w3.org/2003/05/soap-envelope">
  <soap:Body>
    <GetUserDetailsResponse xmlns="http://example.com/">
      <User>
        <Id>123</Id>
        <Name>Иван</Name>
        <Email>ivan@example.com</Email>
      </User>
    </GetUserDetailsResponse>
  </soap:Body>
</soap:Envelope>
```

**Аналогия с рестораном**:
`SOAP` — официант, который работает по очень точным инструкциям и протоколам, где каждая фраза и действие строго регламентированы.

3. **GraphQL**:

    - Современный и гибкий способ общения с `API`, разработанный `Facebook`.

    - Позволяет клиенту точно указать, какие данные ему нужны, и получать только их.

    - Можно делать один запрос, который заменяет несколько запросов в `REST`.

    - Подходит, когда данные сложные и имеют много связей.

**Аналогия с рестораном**:
`GraphQL` — это официант, который внимательно слушает твой заказ и приносит только те блюда и ингредиенты, которые ты попросил, без лишнего.

**Пример запроса GraphQL:**
```graphql
{
  user(id: "123") {
    name
    email
    orders {
      id
      total
    }
  }
}
```
**Пример ответа:**
```json
{
  "data": {
    "user": {
      "name": "Иван",
      "email": "ivan@example.com",
      "orders": [
        { "id": "1", "total": 100 },
        { "id": "2", "total": 150 }
      ]
    }
  }
}
```
4. **WebSocket API**:

    - Позволяет установить постоянное двунаправленное соединение между клиентом и сервером.

    - Используется для приложений в реальном времени: чаты, игры, торговые площадки.

    - Отличается от `REST` и `SOAP` тем, что данные идут постоянно, а не по отдельным запросам.

**Аналогия с рестораном**:
`WebSocket` — это официант, который постоянно рядом с тобой, готов слушать и приносить блюда сразу, как только ты попросишь, без повторных звонков.
