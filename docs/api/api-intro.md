# Введение в API
**Что такое API?**

`API (Application Programming Interface)` — это способ, с помощью которого программы и сервисы могут общаться друг с другом.
Если представить интернет и приложения в виде огромного города, то API — это дороги и мосты, которые соединяют разные части этого города.

**Почему API важны?**

 - Позволяют разным программам работать вместе и обмениваться данными.

 - Дают возможность создавать сложные сервисы из простых частей.

 -  Обеспечивают стандарты, чтобы программы понимали друг друга.

**Как работает API?**

Представь, что API — это официант в ресторане:

 - Ты (клиент) говоришь официанту, что хочешь заказать (отправляешь запрос).

 - Официант передаёт заказ на кухню (серверу).

 - Кухня готовит блюдо и отдаёт официанту (сервер формирует ответ).

 - Официант приносит тебе блюдо (API возвращает данные).

**Виды API**
 - `REST API` — самый популярный тип API, который использует HTTP-протокол для обмена данными.

 - `SOAP` — более сложный и формальный протокол, часто используется в корпоративных системах.

 - `GraphQL` — современный API, который позволяет запросить ровно те данные, которые нужны.

**Основные понятия**

 - `Запрос (Request)` — послание от клиента к серверу с просьбой выполнить действие.

 - `Ответ (Response)` — сообщение от сервера клиенту с результатом выполнения запроса.

 - `Метод (HTTP Method)` — действие, которое клиент хочет выполнить (например, получить данные, создать запись, обновить или удалить).

 - `Статус код` — число, показывающее результат запроса (успех, ошибка и т.д.).

 - `Заголовки (Headers)` — дополнительная информация о запросе или ответе (например, формат данных).

 - `Тело (Body)` — содержимое запроса или ответа (например, данные пользователя).

**Зачем QA знать про API?**

 - API — это часто «средняя прослойка» между фронтендом и бэкендом.

 - Правильное тестирование API позволяет убедиться, что данные и функционал работают корректно.

 - Ошибки на уровне API могут влиять на всю систему, поэтому важно их вовремя находить.
