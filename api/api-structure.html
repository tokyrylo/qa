Структура запроса и ответа в API

Когда ты работаешь с API, каждый запрос и ответ имеет определённую структуру. Понимать, из чего они состоят — очень важно для тестирования и разработки.

Структура HTTP-запроса

  1. Метод (Method):

    • Определяет действие, которое ты хочешь сделать с ресурсом.

    • Примеры: GET, POST, PUT, DELETE, PATCH.

  2. URL (Uniform Resource Locator):

    • Адрес ресурса, к которому обращается запрос.

    • Например:

    https://api.example.com/users/123

  1. Заголовки (Headers):

    • Дополнительная информация о запросе.

    • Например: формат данных (Content-Type), язык (Accept-Language), токены авторизации и т.д.

    • Пример:

    Content-Type: application/json
    Authorization: Bearer <токен>

  1. Тело запроса (Body):

    • Данные, которые отправляются на сервер (если нужно).

    • Используется, например, в POST, PUT, PATCH.

    • Обычно в формате JSON, XML или form-data.

Структура HTTP-ответа 1. Код состояния (Status code):

  • Числовой код, который говорит, успешно ли выполнен запрос.

  • Примеры:

    • 200 OK — всё хорошо, данные вернулись

    • 201 Created — ресурс успешно создан

    • 400 Bad Request — ошибка в запросе

    • 401 Unauthorized — нет доступа (нужно авторизоваться)

    • 500 Internal Server Error — ошибка на сервере

  • Заголовки ответа (Headers):

    • Информация о данных, которые вернул сервер.

    • Например: тип данных (Content-Type), длина содержимого (Content-Length), дата и т.д.

  • Тело ответа (Body):

    • Основные данные, которые возвращает сервер.

    • Например, JSON с информацией о пользователе, ошибке и т.п.

Пример простого запроса и ответа

Запрос

POST /users HTTP/1.1
Host: api.example.com
Content-Type: application/json
Authorization: Bearer abc123

{
  "name": "Иван",
  "email": "ivan@example.com"
}

Ответ

HTTP/1.1 201 Created
Content-Type: application/json

{
  "id": 123,
  "name": "Иван",
  "email": "ivan@example.com"
}

Почему важно знать структуру?:

  • Чтобы понимать, что и куда отправлять.

  • Чтобы проверять, правильно ли сервер реагирует на запросы.

  • Чтобы грамотно писать тесты и находить ошибки.
