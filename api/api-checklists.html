📝 Чеклисты QA для эндпоинтов API

При тестировании API важно иметь структурированный чеклист для каждого эндпоинта. Он помогает не пропустить важные проверки и систематизировать работу QA.

📌 Общие проверки для всех эндпоинтов

  • [ ] Эндпоинт доступен (статус ответа 200/201 для успешного запроса)
  • [ ] Проверка корректного HTTP-метода (GET, POST, PUT, DELETE, PATCH)
  • [ ] Проверка URL и пути (path)
  • [ ] Проверка заголовков запроса (Headers)
  • [ ] Проверка обязательных параметров (query, path, body)
  • [ ] Проверка формата данных в запросе и ответе (JSON, XML, form-data)
  • [ ] Проверка кодов ответа (2xx, 4xx, 5xx)
  • [ ] Проверка сообщений об ошибках
  • [ ] Проверка времени отклика (response time)
  • [ ] Проверка авторизации и токенов (если требуется)

🔹 GET эндпоинты

  • [ ] Возвращает корректные данные
  • [ ] Фильтры и сортировка работают корректно
  • [ ] Пагинация возвращает правильные страницы и элементы
  • [ ] Обработка пустых данных (например, когда ресурсы отсутствуют)
  • [ ] Проверка кеширования и заголовков ETag, Last-Modified

🔹 POST эндпоинты

  • [ ] Успешное создание ресурса
  • [ ] Проверка обязательных и необязательных полей
  • [ ] Проверка валидации данных (тип, длина, формат)
  • [ ] Проверка уникальности полей (например, email, username)
  • [ ] Обработка некорректного JSON
  • [ ] Проверка кода ответа 201 Created и содержимого тела ответа

🔹 PUT / PATCH эндпоинты

  • [ ] Успешное обновление ресурса
  • [ ] Проверка частичного обновления (PATCH)
  • [ ] Проверка валидации данных
  • [ ] Проверка кода ответа 200 OK и обновлённого содержимого

🔹 DELETE эндпоинты

  • [ ] Успешное удаление ресурса
  • [ ] Проверка кода ответа 204 No Content
  • [ ] Проверка удаления связанных данных (если есть зависимости)
  • [ ] Проверка повторного удаления (должно возвращать 404)

🔹 Безопасность и авторизация

  • [ ] Доступ без токена запрещён (401 Unauthorized)
  • [ ] Доступ с неправильным токеном запрещён
  • [ ] Проверка прав пользователя (RBAC)
  • [ ] Проверка CSRF и других защитных механизмов

🔹 Негативные сценарии

  • [ ] Некорректный формат JSON
  • [ ] Пропущенные обязательные поля
  • [ ] Неверные типы данных
  • [ ] Недоступный сервер или таймаут
  • [ ] Ошибки 4xx и 5xx корректно обрабатываются и логируются

⚠️ Совет: можно создать отдельный чеклист для каждого эндпоинта с конкретными параметрами и ожидаемыми результатами, чтобы быстро проверять их после изменений в API.
