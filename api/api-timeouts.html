🌐 Тестирование ошибок сети и таймаутов

При тестировании API важно проверять, как сервер и клиент ведут себя при проблемах сети или длительном ожидании ответа. Такие проверки помогают выявить уязвимости и ошибки в обработке исключительных ситуаций.

📌 Основные сценарии

  1. Таймауты запроса
  2. Сервер долго отвечает → клиент должен корректно завершить запрос

  3. В Postman или Insomnia можно задать таймаут вручную

  4. Отсутствие сети

  5. Сервер недоступен → клиент должен отобразить понятное сообщение об ошибке

  6. Эмуляция отключения интернета или недоступного хоста

  7. Нестабильная сеть

  8. Пакеты теряются или приходят с задержкой

  9. Проверка повторной отправки запросов и корректного восстановления соединения

  10. HTTP ошибки сети

  11. 502 Bad Gateway
  12. 503 Service Unavailable
  13. 504 Gateway Timeout

🚀 Как тестировать

1. Таймауты

  • В Postman:
  • Настрой Request Timeout на низкое значение (например, 1000 мс)
  • Отправь запрос к эндпоинту с задержкой
  • Ожидаемый результат: Request timeout и корректная обработка ошибки
  • В коде: проверить, что клиент не "виснет" при долгом ответе сервера

2. Недоступный сервер

  • Изменить URL на несуществующий хост
  • Ожидаемый результат: Could not resolve host или соответствующая ошибка в клиенте

3. Нестабильная сеть

  • Использовать эмуляторы сетевых условий (например, DevTools → Network Throttling)
  • Проверить корректное повторное подключение и обработку ошибок

4. Симуляция HTTP ошибок

  • Использовать mock-сервер или тестовые данные
  • Генерировать ответы с кодами 502, 503, 504
  • Проверять, что клиент или система отображает корректное сообщение пользователю
