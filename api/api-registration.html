📝 Регистрация пользователя через API

Рассмотрим, как отправить запрос на регистрацию нового пользователя тремя способами: Postman,

🚀 Регистрация в Postman

1. Открой Postman и создайте новый запрос.

  1. В поле метода выбери POST.

3. Введи URL, например:

http://localhost:8000/api/v1/register (*)

4. Перейди во вкладку Headers и добавь:

Content-Type: application/json

  1. Перейди во вкладку Body, выбери raw и формат JSON.

  2. Вставь тело запроса:

{
  "email": "user10@example.com",
  "username": "test_user",
  "password": "Qq!123456",
  "name": "string"
}

  1. Нажми Send — внизу появится ответ от сервера

Регистрация в Insomnia

  1. Создай новый запрос (New Request).

  2. Выбери метод POST и укажи URL:

http://localhost:8000/api/v1/register (*)

  1. Во вкладке Body выбери JSON.

  2. Вставь:

{
  "email": "user11@example.com",
  "username": "test_user",
  "password": "Qq!123456",
  "name": "string"
}

  1. Нажми Send и проверь ответ.

Регистрация в Swagger UI

  1. Перейди на страницу Swagger-документации API (например, http://localhost:8000/api/v1/register).

  2. Найди эндпоинт POST /api/v1/register.

  3. Нажми Try it out.

  4. Заполни поля:

  5. "email": "user12@example.com"

  6. "username": "test2_user"
  7. "password": "Qq!123456"
  8. "name": "string"

Нажми Execute — Swagger покажет и отправленный запрос, и ответ от сервера.

Если при регистрации возвращается ошибка 400 Bad Request, проверь:

  • правильность формата JSON (кавычки, запятые);

  • обязательные поля;

  • уникальность email.

🧪 Чеклист QA для регистрации пользователя

1. Позитивные сценарии

  • [ ] Создать нового пользователя с корректными данными → ожидается 201 Created.
  • [ ] Проверить, что в ответе возвращается id, email, username.
  • [ ] Убедиться, что пользователь реально появился в базе данных (если есть доступ к бэку).

2. Негативные сценарии

  • [ ] Попробовать зарегистрировать пользователя без обязательных полей (email, password) → ожидается 400 Bad Request.
  • [ ] Попробовать зарегистрировать пользователя с некорректным форматом email → 400 Bad Request.
  • [ ] Попробовать зарегистрировать пользователя с уже существующим email или username → 409 Conflict или 400 Bad Request.
  • [ ] Попробовать отправить некорректный JSON (например, пропущенная скобка или кавычка) → 400 Bad Request.

3. Проверка формата данных

  • [ ] Убедиться, что все строки в JSON заключены в двойные кавычки.
  • [ ] Проверить, что длина пароля соответствует требованиям (если есть правила: min/max длина, спецсимволы).
  • [ ] Проверить, что дополнительные поля игнорируются или вызывают корректную ошибку.

4. Безопасность

  • [ ] Убедиться, что пароль не возвращается в теле ответа.
  • [ ] Проверить, что при успешной регистрации сразу не выдаётся токен (если логика API разделяет регистрацию и авторизацию).

5. Инструменты

  • [ ] Провести все сценарии через Postman, Insomnia, Swagger.
  • [ ] Проверить, что все эндпоинты возвращают корректные HTTP-коды.
  • [ ] Проверить, что ошибки сопровождаются понятным сообщением.
