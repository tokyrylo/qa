📜 Логирование и мониторинг

Логирование и мониторинг — это ключевые инструменты QA для обнаружения, анализа и предотвращения проблем в API и приложениях.

🔹 Логирование

Логирование — это процесс записи событий, ошибок и технической информации во время работы приложения или API.

Что логировать (с точки зрения QA):

  • Запросы и ответы API (метод, URL, заголовки, тело запроса/ответа).
  • Ошибки (статус-коды, исключения, сообщения об ошибках).
  • Время выполнения запроса (для поиска узких мест).
  • Системные события (перезапуск сервера, сбои).

Пример формата логов:

[2025-08-15 12:34:56] INFO: Request POST /api/v1/login
[2025-08-15 12:34:56] DEBUG: Payload: {"email": "user@example.com"}
[2025-08-15 12:34:56] INFO: Response 200: {"access_token": "..."}

Рекомендации для QA:

  • Проверяй, что в логах не попадают пароли и токены.
  • Логи должны быть читаемыми и структурированными (JSON или текст).
  • Используй корреляционные ID (trace-id) для связывания запросов и ответов.

🔹 Мониторинг

Мониторинг — это процесс отслеживания состояния API и инфраструктуры в реальном времени.

Что можно мониторить:

  • Доступность API (работает ли эндпоинт).
  • Время отклика (latency).
  • Частоту ошибок (error rate).
  • Нагрузку (количество запросов, CPU, RAM).

Инструменты:

Инструмент Описание
Prometheus + Grafana Мониторинг метрик и построение графиков.
Elastic Stack (ELK) Сбор и анализ логов, поиск ошибок.
Sentry Отслеживание исключений и ошибок в реальном времени.
New Relic / Datadog Комплексный APM, мониторинг и алерты.
Pingdom / UptimeRobot Проверка доступности API.

🔹 Роль QA в логировании и мониторинге

  • Проверять, что все ошибки API логируются корректно.
  • Убедиться, что алерты срабатывают при сбоях.
  • Тестировать систему на объём логов при нагрузке.
  • Проверять, что чувствительные данные не сохраняются в логах.

📌 Чеклист для QA

  • [ ] Логи пишутся для всех запросов и ошибок.
  • [ ] Логи не содержат пароли, токены и конфиденциальную информацию.
  • [ ] Формат логов структурированный (JSON или единый шаблон).
  • [ ] Мониторинг показывает корректные метрики.
  • [ ] Есть уведомления (alert) при падении сервиса или росте ошибок.
