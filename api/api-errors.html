⚠️ Типичные ошибки в API и как их находить

1. Неверные статус-коды

Проблема:
API возвращает неправильный HTTP-статус (например, 200 OK при ошибке, или 500 при ошибке клиента).

Как находить:
- Сравни статус-код с ожидаемым по документации.
- Проверяй с помощью Postman, curl или автотестов.
- Примеры: - ❌ 200 вместо 404 при запросе несуществующего ресурса. - ❌ 500 вместо 400 при некорректных данных.

2. Несоответствие формата данных

Проблема:
Ответ не в том формате (ожидаешь JSON, а приходит HTML или текст).

Как находить:
- Проверяй заголовок Content-Type.
- Валидируй JSON через jsonlint.com или встроенные проверки в тестах.

3. Пропавшие или лишние поля

Проблема:
В ответе нет обязательных полей или появляются неожиданные.

Как находить:
- Сверяй ответ с API-документацией.
- Пиши тесты, которые проверяют наличие и тип данных каждого поля.

4. Некорректные типы данных

Проблема:
Поле price приходит как строка "100" вместо числа 100.

Как находить:
- Проверяй типы данных (JSON Schema, автотесты).
- Обрати внимание на даты и булевы значения.

5. Логические ошибки в данных

Проблема:
Данные есть, но они неверные: - Цена товара отрицательная. - Дата доставки в прошлом. - ID пользователя не совпадает с запрошенным.

Как находить:
- Сравнивай ответы с ожидаемым результатом.
- Добавляй проверки бизнес-логики в тесты.

6. Медленные ответы

Проблема:
Запрос обрабатывается слишком долго (> 1–2 секунд для простых операций).

Как находить:
- Меряй время ответа в Postman, curl или JMeter.
- Смотри, есть ли просадки при большом количестве запросов.

7. Ошибки безопасности

Проблема:
- Можно получить чужие данные. - В ответе есть пароли или токены. - API не проверяет авторизацию.

Как находить:
- Пробуй запросы без авторизации или с неверным токеном.
- Проверь, что приватные поля не возвращаются.
- Ищи в ответах служебную информацию.

8. Необработанные ошибки

Проблема:
При сбое API возвращает пустой ответ или технический текст вместо понятного JSON-ответа об ошибке.

Как находить:
- Ломай запросы специально (неверные параметры, метод).
- Проверяй, что в ответе есть структура ошибки (код, сообщение).
