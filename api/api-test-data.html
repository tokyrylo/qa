📝 Работа с тестовыми данными в API

Тестовые данные помогают проверять API без воздействия на реальные данные и пользователи. Они необходимы для безопасного и предсказуемого тестирования.

1. Типы тестовых данных

  • Фиксированные (static)
    Данные заранее подготовлены и используются для предсказуемых тестов.
    Пример: пользователь с email test@example.com и паролем Qq!123456.

  • Динамические (generated)
    Данные создаются на лету при запуске тестов.
    Пример: случайный email user1234@example.com, случайный пароль.

  • Граничные (edge cases)
    Используются для проверки ограничения форматов, длин строк, числовых диапазонов.
    Пример: пароль длиной 1 символ или очень длинный email.

  • Негативные (invalid)
    Данные, которые нарушают правила API, чтобы проверить обработку ошибок.
    Пример: email без @, пустой пароль.

2. Работа с тестовыми пользователями

  • Создавайте отдельный аккаунт для тестов, чтобы не мешать реальным данным.
  • При необходимости используйте автоматическое создание и удаление пользователей через API.
  • Храните учетные данные в защищенном месте (например, .env или секреты CI/CD).

3. Использование фикстур и моков

  • Фикстуры — заранее подготовленные данные для тестов.
  • Моки — имитация внешних сервисов для изоляции тестируемого API.
  • Позволяют тестировать API без зависимости от внешних систем и базы данных.

4. Примеры в Postman / Insomnia

  • Создайте коллекцию тестов и добавьте переменные окружения для тестовых данных:
  • {{test_email}}
  • {{test_password}}
  • Используйте эти переменные в теле запроса и заголовках.
  • Пример запроса регистрации с переменными:
{
  "email": "{{test_email}}",
  "username": "test_user",
  "password": "{{test_password}}",
  "name": "Тестовый пользователь"
}

✅ Чеклист QA: Работа с тестовыми данными

Используй этот список для проверки корректности и безопасности тестирования API.

1. Подготовка тестовых данных

  • [ ] Созданы отдельные тестовые пользователи и ресурсы.
  • [ ] Используются динамические данные для уникальности (например, email).
  • [ ] Подготовлены негативные и граничные данные.
  • [ ] Проверено, что фикстуры и моки соответствуют реальным схемам данных.

2. Использование тестовых данных в запросах

  • [ ] Тестовые переменные корректно подставляются в запросы ({{test_email}}, {{test_password}}).
  • [ ] Проверены все методы API: GET, POST, PUT, DELETE.
  • [ ] Проверка с валидными данными.
  • [ ] Проверка с невалидными данными.
  • [ ] Проверка с граничными значениями (min/max длина, числа, даты).

3. Очистка данных после теста

  • [ ] Все временные пользователи и записи удаляются.
  • [ ] Проверено, что удаление не затрагивает реальные данные.
  • [ ] Сессии и токены очищены после тестирования.

4. Безопасность и конфиденциальность

  • [ ] Тестовые данные не содержат реальной персональной информации.
  • [ ] Пароли и секретные ключи хранятся в защищённых переменных окружения.
  • [ ] Генераторы данных создают безопасные значения (например, сложные пароли).

5. Мониторинг и логирование

  • [ ] Логи запросов и ответов хранятся для отладки.
  • [ ] Исключены секретные данные из логов.
  • [ ] Проверено, что тестовые данные не попали в production.

6. Примеры использования в Postman / Insomnia

  • [ ] Переменные окружения корректно создаются и используются.
  • [ ] Коллекции запросов используют тестовые данные.
  • [ ] Проверены сценарии регистрации, авторизации и CRUD операций с тестовыми данными.
