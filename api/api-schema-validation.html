📊 Проверка схем данных (JSON Schema / OpenAPI)

Когда API возвращает данные, важно убедиться, что они соответствуют ожидаемой структуре. QA проверяет не только наличие полей, но и их типы, обязательность и ограничения.

📌 Основные цели проверки схемы

  1. Типы данных
  2. Проверка, что поле имеет правильный тип (string, integer, boolean, array, object).

  3. Пример: json { "id": 123, // integer "name": "Иван", // string "is_active": true // boolean }

  4. Обязательные и опциональные поля

  5. Поля, которые всегда должны присутствовать (required), и те, что могут отсутствовать.

  6. Пример: json { "email": "user@example.com", // required "phone": null // optional }

  7. Форматы и ограничения

  8. Проверка формата данных (email, date-time, uuid) и ограничений (minLength, maxLength, enum).

  9. Пример: json { "status": "active", // enum: ["active", "inactive"] "created_at": "2025-08-15T12:00:00Z" // date-time }

  10. Массивы и вложенные объекты

  11. Проверка структуры массивов и объектов внутри объектов.
  12. Пример: json { "users": [ { "id": 1, "name": "Иван" }, { "id": 2, "name": "Мария" } ] }

🛠 Инструменты для проверки схем

  • Postman
  • Возможность проверять поля и типы через тесты на JavaScript.
  • Swagger / OpenAPI
  • Автоматически валидирует ответы сервера согласно описанной схеме.
  • JSON Schema Validator
  • Онлайн-сервисы или библиотеки на Python/JS для проверки JSON по схеме.
  • Automated QA Scripts
  • Скрипты для проверки структуры и типов полей в ответах API.

✅ Рекомендации QA

  • Всегда проверяй ключевые поля, их типы и форматы.
  • Убедись, что обязательные поля всегда присутствуют, а опциональные корректно обрабатываются при отсутствии.
  • Для массивов проверяй структуру каждого элемента.
  • Документируй несоответствия схемы и проверяй их после исправлений.

📝 Чеклист QA: Проверка схем данных API

Используйте этот чеклист, чтобы убедиться, что ответы API соответствуют ожидаемой структуре и требованиям.

1. Общие проверки

  • [ ] Ответ имеет корректный HTTP статус (200, 201, 400, 401 и т.д.)
  • [ ] Content-Type ответа соответствует ожидаемому (application/json, application/xml)
  • [ ] Тело ответа не пустое (если ожидалось наличие данных)

2. Типы данных

  • [ ] Поля имеют правильный тип (string, integer, boolean, array, object)
  • [ ] Поля с числами не содержат строки
  • [ ] Поля с логическим типом (boolean) содержат только true или false

3. Обязательные и опциональные поля

  • [ ] Все обязательные поля присутствуют в ответе
  • [ ] Опциональные поля корректно обрабатываются при отсутствии
  • [ ] Нет лишних полей, которых нет в документации

4. Форматы и ограничения

  • [ ] Поля с форматом email, uuid, date-time соответствуют стандарту
  • [ ] Поля с перечислениями (enum) содержат только допустимые значения
  • [ ] Проверены ограничения длины (minLength, maxLength) и числовые ограничения (minimum, maximum)

5. Массивы и вложенные объекты

  • [ ] Массивы содержат элементы правильного типа
  • [ ] Каждый объект в массиве соответствует схеме
  • [ ] Вложенные объекты имеют правильную структуру и все обязательные поля

6. Ошибки и исключения

  • [ ] Проверка структуры ответа при ошибках (4xx, 5xx)
  • [ ] Сообщение об ошибке содержит обязательные поля (code, message, details)
  • [ ] Типы данных в ошибках корректны

7. Автоматизация

  • [ ] Написаны тесты для проверки схемы на Postman / Insomnia / Automated QA
  • [ ] Проверка схемы интегрирована в CI/CD (если возможно)
