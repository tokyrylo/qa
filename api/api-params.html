Параметры запроса в API

Параметры — это дополнительные данные, которые помогают серверу понять, что именно вы хотите получить или изменить. Они влияют на запрос и позволяют более точно указать нужную информацию.

Основные типы параметров

  1. Query Parameters (Параметры запроса):

    • Передаются в URL после знака вопроса?.

    • Состоят из пар ключ=значение, разделённых амперсандом &.

    • Используются, чтобы фильтровать, сортировать или ограничивать данные.

Пример:

GET /products?category=books&sort=price_asc HTTP/1.1
Host: api.example.com

- Здесь мы просим товары из категории "`books`" и хотим отсортировать по цене по возрастанию.

  1. Path Parameters (Параметры пути):

    • Это часть URL, которая динамически меняется и указывает на конкретный ресурс.

    • Обычно выделяются в документации как переменные.

Пример:

GET /users/123 HTTP/1.1
Host: api.example.com

- Здесь **123** — это `path parameter`, обозначающий ID пользователя.

  1. Body Parameters (Параметры тела запроса):

    • Это данные, которые отправляются в теле запроса (часто в POST, PUT, PATCH).

    • Обычно формат — JSON, XML или form-data.

    • Используются, чтобы передать новые данные или обновления.

Пример (JSON тело):

{
  "name": "Ольга",
  "email": "olga@example.com"
}

Краткое сравнение

Тип параметров Где передаются Для чего используются
Query В URL после ? Фильтры, сортировка, поиск
Path В части URL (путь) Указание конкретного ресурса (например, по ID)
Body В теле HTTP-запроса Передача новых данных или изменений

Почему это важно для QA?

  • Нужно правильно формировать запросы, чтобы получать ожидаемый результат.

  • Проверять, как сервер реагирует на разные параметры — корректно ли фильтрует, обрабатывает ли данные и т.п.

  • Понимать, где искать нужные параметры в документации.
